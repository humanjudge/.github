## What we're building

Production AI fails in ways current evaluation can't catch.

Our center of gravity is **post-deployment evaluation**. We treat live evaluation as a **datastream, not a fixed dataset** — capturing pluralistic, multi-user, multi-context feedback continuously, and keeping the signal rich rather than collapsing it to a single score.

## The R&D community

An open community working in public around six research streams in pluralistic evaluation for AI agents in production. Anchored at the [Berkeley RDI Agentic AI Summit, Aug 1–2 2026](https://rdi.berkeley.edu/) (confirmed poster presenter spot).

| Stream | Topic |
|---|---|
| **0 — Applied training** | Wire pluralistic streams into existing methods (KTO, DPO, GRPO, MOPO). Aggregation rule research. |
| **1 — Resource curation** | Public opinionated index of AI safety + production-evaluation tools. |
| **2 — Selector mechanism** | "Pick The Right Brain" — model routing driven by live feedback. |
| **3 — Public guardrailing** | Runtime guardrail updates from production signals. |
| **4 — Pluralistic signal** | Twin threads: input vocabulary (4-A) + public accountability artifacts (4-B). |
| **5 — UI integration** | HumanJudge signal anywhere developers work — Langfuse, n8n, Cursor, Slack, and more. |

[Detailed descriptions in the main repo →](https://github.com/humanjudge/grandjury#research-community)

## Apply by opening a PR

No CV, no application form. Open a small PR on [`humanjudge/grandjury`](https://github.com/humanjudge/grandjury) with a challenge result and which streams interest you. Reviewed personally within ~3 business days. After merge: Discord access instructions arrive via GitHub.

[See the apply walkthrough →](https://github.com/humanjudge/grandjury/blob/master/CONTRIBUTING.md#apply-to-the-rd-community)
